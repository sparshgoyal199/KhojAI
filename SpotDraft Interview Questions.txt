Q3 Why SSE?
Ans3. First of all understand the SSE is not the thing which enables the persistence connection and send multiple data to the frontend (These things enable through streaming Response and Async generator function). SSE just defined the boundary about how to parse those data in frontend, in simpler words it makes the parsing of data in frontend easy. because it is not like that ki there is consistency in sending the events, like generate one chunk and send its byte only to frontend. there is not such type of consistency exist. it is possible that we can send multiple events as one packet, and it is also possible to send one event in two or more than two split ways, so SSE is a protocol which help us to recieve the exact token created at application level. It help us to retrieve the exact chunk send by the server, 

Q4 How are you generating summary?
Ans4. 	(0) Cluster basically seperates the different topics
	(1) Using Kmeans-clustering
	(2) suppose i have 5 clusters, distributed all my vectors to 5 clusters
	(3) Each cluster will have all the vectors which are closer to each other
	(4) compute the mean of that cluster
	(5) then find for each cluster which vector is close to its mean cluster
	(6) then the corresponding chunk payload to that vector will be my summary chunk
